\subsection{Trigger-Slot Array and Programming Model}
Each logical processor owns an array of at least four trigger slots. The implementation reports the exact count through
CPUID \texttt{DEBUG\_TRIGGERS.SLOT\_COUNT}. Trigger state is accessed by the supervisor-only
\texttt{DTRSEL}/\texttt{DTRDATA} selector-data pair. \texttt{DTRSEL.SLOT} selects a slot and
\texttt{DTRSEL.BANK} selects the word read or written through \texttt{DTRDATA}.

A slot is staged while \texttt{VALID=0}. Software writes CONFIG, LOW, and HIGH in any order, then writes
\texttt{VALID=1} as the final operation. Activation atomically validates that LOW is less than HIGH, at least one of
X/R/W is set, at least one of U/S is set, and every reserved bit is zero. To replace an active slot, software first
writes its current CONFIG image with only VALID cleared. While active, no other CONFIG change and no LOW or HIGH write
is permitted. A rejected write changes neither the slot nor the selector.
