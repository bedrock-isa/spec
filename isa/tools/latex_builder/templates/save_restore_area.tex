\section{SAVE/RESTORE Processor-State Save Area}

SAVE and RESTORE use a CPUID-defined memory image. The save-area base is 4 KiB aligned, and extension component
slots are 64-byte aligned.

The fixed base block records the architectural integer state required for user-level context save. Extension
components are present only when the state-block bitmap and CPUID component description indicate that the component
is enabled and saved.

RESTORE is the inverse operation for a valid save image. User-mode RESTORE ignores saved supervisor-only STATUS
state; supervisor RESTORE applies the normal STATUS write rules.

The fixed block records R0 through R15, GS validity bits and any implemented GS images, FLAGS, and STATUS. The GS
validity bitmap determines which GS0 through GS4 images are present. CPUID SAVE\_AREA\_LAYOUT leaves describe the
offset and maximum size of every extension component, and each extension slot begins on a 64-byte boundary.

SAVE may omit an architecturally clean extension block by clearing its state-block bitmap bit. RESTORE treats the
bitmap as authoritative when reconstructing extension state. A user-mode restore never imports supervisor-only
STATUS state; a supervisor restore validates the saved STATUS image by the ordinary privileged write rules before
making it visible.
