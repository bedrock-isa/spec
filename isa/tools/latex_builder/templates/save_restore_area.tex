\section{Processor-State Save and Restore}

SAVE and RESTORE use a CPUID-defined memory image whose base is 4 KiB aligned. The fixed block contains the base
header, state-block bitmap, R0 through R15, and optional GS0 through GS5 images.

The header carries FLAGS, STATUS, format, and GS-validity state. \texttt{GS\_VALID} selects which GS images are
meaningful. SAVE may omit an architecturally clean extension component by clearing its bitmap bit, and RESTORE uses
that bitmap as authoritative when reconstructing extension state.

User-mode RESTORE ignores saved supervisor-only STATUS state. Supervisor RESTORE validates the saved STATUS image by
the ordinary privileged write rules before making it visible.

CPUID \texttt{SAVE\_AREA\_LAYOUT} leaves report every extension component's offset and maximum size. Each component
starts on a 64-byte boundary; software does not infer one offset from another component's size. When floating-point
state is enabled, its component contains F0 through F15, FFLAGS, and FSTATUS.
