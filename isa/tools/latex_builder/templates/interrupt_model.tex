Exception processing covers synchronous restartable CPU exceptions, traps, NMIs, external interrupts, and the
supervisor-entry state needed to return from them.

The processor records a restartable context for CPU exceptions. The operating system decides whether that
context is retried, emulated, reported, or terminated.

\subsection{Interrupt Vector Table}
The interrupt vector table occupies one 4096-byte page selected by ICR.ivt\_page. It contains 256 fixed-size
entries, each 16 bytes. The vector number selects the entry at ICR.ivt\_page * 4096 + vector * 16.

Bytes 0 through 7 contain the 64-bit interrupt handler address. Byte 8 is the entry control byte. HP is the
handler-present bit; if it is clear, delivery immediately becomes DOUBLE\_FAULT. SN selects the supervisor stack
set used for the entry frame. Reserved IVT bits must be written as zero.

\subsection{Vector Assignment}
Vectors 0x00..0x1F are owned by the CPU architecture. Vectors 0x20..0x3F are reserved for future architectural
use. Operating systems, platforms, and devices may assign vectors 0x40..0xFF.

SYSCALL does not allocate or consume an IVT vector. It enters supervisor mode through the SPC/SCS/SDS
supervisor-entry path.

\subsection{Entry and Return Rules}
Exception entry is precise at the architectural instruction boundary or at the instruction-defined restart point.
Completed earlier instructions remain committed; the faulting operation reports enough state for restart or
emulation.

IRET restores the saved execution context after validating the saved segment and status fields. Invalid saved
state raises the appropriate control-state exception instead of partially returning.

\subsection{Supervisor Entry Stack Frame}
The fixed supervisor-entry frame is 64 bytes: eight 64-bit slots. FRAME\_CONTROL.frame\_size records the total
frame size in 8-byte units, so the base frame records 8 units before any optional payload.

Offsets are measured from the saved stack pointer. Optional payload, when present, follows the fixed frame in
whole 64-byte blocks.

\texttt{FRAME\_CONTROL.frame\_type} documents the stack frame format. Payload, if any, is appended after the
fixed frame in whole 64-byte blocks. \texttt{FRAME\_CONTROL.frame\_size} gives the total number of 8-byte slots,
and the frame type code determines how software interprets the allocated payload blocks. IRET does not validate
the frame type.

\subsection{Repeat Fault Continuation}
When FRAME\_CONTROL.rep\_fault is set, the FAULT\_AUX payload records the active repeat context. The saved PC is
the faulting scalar instruction or the faulting instruction inside a REPG group.

For REPG, software reconstructs the group start from the saved fault PC and the encoded group-start delta.
Returning with IRET preserves the continuation state unless software edits the frame before return.

\subsection{Interrupt Reset State}

@RESET_STATE_TABLE@

Reset initializes the processor into a supervisor-controlled state with interrupts disabled and
implementation-defined reset vector state supplied by the platform. Software must initialize segment state,
translation controls, interrupt-vector state, and any enabled extension state before entering ordinary user
execution.
