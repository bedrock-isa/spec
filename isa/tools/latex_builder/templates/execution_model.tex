This section defines the common execution contract used by the instruction descriptions. An individual
instruction may add stricter rules, but it does not silently replace the rules below. The purpose of this section
is to make operand evaluation, side effects, repetition, and status updates readable before the per-instruction
pages.

\subsection{Instruction Boundary and Default Execution Rules}
The instruction boundary is fixed by the first two instruction bytes before operand evaluation begins. An
implementation may reject an instruction before any architectural state is changed if the encoded length cannot
contain the selected form.

The encoded length must contain every required opcode byte, prefix word, descriptor, immediate, displacement,
bitmap, and instruction-specific payload. Extra payload bytes are part of the instruction record but have no
implicit extension meaning unless the selected instruction form consumes them.

\subsection{Instruction Boundary, Operand Evaluation, and EA Defaults}
Operands are decoded in instruction order. Source reads complete before the final destination write unless an
atomic form says otherwise. Effective-address calculation may produce an address without reading memory.

Auto-update EA forms update a temporary operand-evaluation image. The architectural register update becomes
visible only when the instruction commits.

\subsection{Mnemonic Suffix Rules}
The B, W, L, and Q suffixes select 8-, 16-, 32-, and 64-bit integer operation size. S and D suffixes select
32- and 64-bit floating-point scalar size where the floating-point instruction group defines them.

If an instruction form encodes a size selector z, the instruction definition maps z to the suffix set shown by
that form. A mnemonic without a size suffix has a single architecturally defined size or no data-size operand.
Conditional mnemonic forms use the condition names listed in the Condition Codes section.

\subsection{Operand and Status Notation}
Rn names a general-purpose register. SP and PC are special registers outside the Rn encoding namespace. An
\texttt{<ea>} operand names a compact effective-address field and any appended EA payload required by that field.

FLAGS, STATUS, FFLAGS, and FSTATUS are architectural state registers. Instruction descriptions state whether a
form updates, preserves, reads, or ignores each status field.

\subsection{Shared Side-Effect Rules}
An instruction that faults before commit leaves destination registers, destination memory, and auto-update
register effects unchanged unless the instruction explicitly defines partial completion.

Atomic read-modify-write forms have a single architectural commit point for the memory update and any associated
register result. Cache, TLB, and system-state instructions describe their own serialization and visibility rules.
