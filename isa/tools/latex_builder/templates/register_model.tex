\section{Programming Model}

\subsection{Register Model}
The integer programming model exposes sixteen 64-bit Rn registers, R0 through R15. Bedrock uses one
general-purpose register class for integer values, address values, counters, selectors, and temporary data.

SP and PC are special architectural registers outside the four-bit Rn namespace. SP-relative memory forms use SS by
default; PC-relative memory forms use CS by default.

Segment registers are separate 64-bit architectural registers. Segment-qualified EA forms select them explicitly,
while SP and PC forms omit the segment field because their segment association is fixed.

\subsection{Unified Integer Register File}
The base architecture has no data-register bank mechanism. All integer instructions address the same architectural R0
through R15 register file.

Bank-select instructions and banked integer-register control state are outside this ISA definition and are not
accepted as instruction or control-state features.

\subsection{Floating-Point Register Model}
The floating-point extension exposes F0 through F15 as independent 64-bit registers when the floating-point
instruction group is implemented.

Floating-point exception and mode state is held separately in FFLAGS and FSTATUS. Their precise bit assignments are
defined by the floating-point instruction set and compatibility state.

\subsection{Segment Register Operand Class}
Instructions that take an explicit segment-register operand use the three-bit SREG encoding below.

SP-relative EA forms do not carry this field and use SS. PC-relative EA forms do not carry this field and use CS.

\begin{manualtabular}{@{}>{\raggedright\arraybackslash}p{0.60in}>{\raggedright\arraybackslash}p{0.50in}>{\raggedright\arraybackslash}p{4.30in}@{}}
\toprule
\textbf{SREG} & \textbf{Bits} & \textbf{Use}\\
\midrule
\texttt{CS} & \texttt{000} & code segment; instruction fetch and PC-relative default\\
\texttt{DS} & \texttt{001} & default data segment\\
\texttt{SS} & \texttt{010} & stack segment; fixed for SP-relative forms\\
\texttt{GS0} & \texttt{011} & TLS context in the ELF and C ABIs\\
\texttt{GS1} & \texttt{100} & general segment 1\\
\texttt{GS2} & \texttt{101} & general segment 2\\
\texttt{GS3} & \texttt{110} & general segment 3\\
\texttt{GS4} & \texttt{111} & volatile far-data window in bedrock-c-far; otherwise target-specific\\
\bottomrule
\end{manualtabular}

\subsection{Control Registers}
Control registers are accessed only through the architectural control-register instructions and obey the reserved-bit
rules in the compatibility section.

The complete selector namespace, field formats, access rules, and reserved-bit behavior are specified in the RDCR and
WRCR instruction descriptions. The namespace covers translation, interrupt delivery, supervisor entry, boot state,
and performance monitoring without duplicating the selector table here.
