This section defines the default compatibility contract for reserved fields, optional features, and future
architectural growth. A later section may narrow one of these defaults for a specific structure, but it must say so
explicitly.

Reserved and unallocated are the same architectural category in this manual: software must not depend on a current
value, decode result, or behavior for a reserved encoding or field.

\subsection{Reserved Fields}
Architected registers and architectural memory structures use these defaults unless their defining section gives a
narrower rule.

Software-defined fields are not reserved fields. Software may store values in them, and hardware ignores them except
where the containing structure explicitly says otherwise.

\subsection{Reserved Encodings}
Reserved instruction opcodes, reserved extension opcodes, reserved effective-address forms, and unsupported optional
instruction-group encodings are not executable instruction forms.

There is no separate extension-unavailable exception in this model; unsupported optional instruction-group encodings
use the same illegal-instruction path as other reserved instruction encodings.

Prefix bytes are metadata, not instruction opcodes. Unassigned prefix values remain reserved for future prefix
definitions and currently have no architectural effect.

Noncanonical encodings are invalid unless an instruction description explicitly defines an alias or priority rule.
Assemblers emit canonical encodings by default; disassemblers prefer canonical spellings.

\subsection{CPUID Compatibility}
CPUID is the compatibility boundary for optional architectural behavior. Software must not use an optional
instruction group, optional register state, or optional state image unless the corresponding CPUID bit or leaf
reports support.

Unknown selectors return zero. Reserved CPUID result bits are ignored by software unless a future architectural
definition assigns them.
