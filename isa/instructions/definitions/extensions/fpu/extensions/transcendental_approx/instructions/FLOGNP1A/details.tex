The required FPTRANSA\_ACCURACY contract is \texttt{0x0042}. If that accuracy contract's \texttt{PRESENT} field is clear, the instruction raises \texttt{ILLEGAL\_INSTRUCTION} before reading operands or floating-point state.

After FSTATUS.DAZ processing, the reference function is ln(1 + x) without an intermediate rounded addition on finite x \textgreater{}= -1 and positive infinity; -1 is the DZ boundary. The result error is at most 4 ULP for S and 4 ULP for D.

\textbf{Special values}\par
\begin{itemize}
\item When the source equals -1, DZ is generated and the result is -infinity.
\item When the source \textless{} -1, NV is generated and the result is the architectural default quiet NaN.
\item When the source is +infinity, the result is +infinity.
\item When the source is zero, the result is the source.
\end{itemize}

\textbf{Exact anchors}\par
\begin{itemize}
\item log1p(+0) = +0
\item log1p(-0) = -0
\item log1p(-1) = -infinity
\end{itemize}

\textbf{Required properties}\par
\begin{itemize}
\item strictly increasing on (-1, +infinity)
\end{itemize}

NaN handling, floating-point exception-cause generation, matching condition-enable testing, \texttt{FLOATING\_POINT\_FAULT} architectural-event delivery, and commit behavior follow the common FPTRANSA model in Section~\ref{section:fptransa-common-model}.
