SAVE writes base (:term:base.terms.architectural_state:) and modified enabled extension state to a 4-KiB-aligned, CPUID-defined save area.

SAVE treats its address-role EA as the base of the save area without first reading an EA-sized operand. It writes the fixed base block, (:ref:base.state.save_area.BASE_HEADER.FMT:)\texttt{=0}, (:ref:base.state.save_area.BASE_HEADER.GS_VALID:)\texttt{=0x3f}, the state-block bitmap, R0 through R15, GS0 through GS5, (:ref:base.state.save_area.BASE_HEADER.FLAGS:), (:ref:base.state.save_area.BASE_HEADER.STATUS:) including (:ref:base.registers.STATE.STATUS.EDEPTH:) and (:ref:base.registers.STATE.STATUS.UO:), and the hidden (:ref:base.state.save_area.BASE_HEADER.DFA:) bit according to the Processor-State Save and Restore layout. Enabled modified extension components are written to their CPUID-defined offsets; a component known to equal its initial state may be omitted and reported clear in the bitmap. SAVE does not change a component\textquotesingle{}s clean or modified state.

The complete (:ref:base.cpuid.IMPLEMENTATION.SAVE_AREA_LAYOUT.SAVE_AREA_SIZE.SAVE_AREA_SIZE_BYTES:) range reported by CPUID is validated before any byte is written. Any address or access fault leaves the architectural register state and save area unchanged.
