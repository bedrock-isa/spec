\subsection{Instruction Header Formats}

Instruction framing is byte-oriented. Byte 0 alone identifies extrashort and short instructions; extended
instructions use byte 0 and byte 1 to determine both (:term:base.terms.encoded_instruction_length:) and opcode-space selection.

Extended byte0[5:2] is L, and the (:term:base.terms.encoded_instruction_length:) is 3+L bytes. The opcode-space allocation bits begin at
byte0[1:0], continue through byte1, and then through later opcode-space bytes as required by the encoding class.

An extended instruction is invalid if its (:term:base.terms.encoded_instruction_length:) is shorter than the opcode-space length: 3 bytes
for medium, 4 bytes for long, 5 bytes for extralong, and 6 bytes for xxlong.

The first eight allocation bits select the extended (:term:base.terms.opcode_space:).
The value \texttt{11111111} selects the xxlong class, whose six-byte (:term:base.terms.opcode_space:) provides 42
allocation bits. The value \texttt{11111110} is (:term:base.terms.reserved:) for custom extensions; it retains extralong framing and is
unallocated by the standard ISA. All other existing selectors retain their class and allocation.

\texttt{LEN n, <instruction>} requests an encoded extended instruction length of \texttt{n} bytes, where
\texttt{3 <= n <= 18}. The requested length must cover the (:term:base.terms.required_instruction_length:). Without \texttt{LEN}, the
assembler emits that required length. It fills requested trailing (:term:base.terms.padding:) with zero. A disassembler emits
\texttt{LEN n,} when the (:term:base.terms.encoded_instruction_length:) exceeds the (:term:base.terms.required_instruction_length:) so reassembly preserves
the length; (:term:base.terms.padding:) byte values are not (:term:base.terms.preserved:). Extrashort and short encodings retain their fixed lengths.

Figure~\ref{fig:instruction-header-byte-formats} annotations are read from high to low bit. In byte 0, bit 7 distinguishes extrashort framing; bits 7..6
select short (\texttt{10}) or extended (\texttt{11}) framing. For short instructions, bits 5..2 and 1..0 continue
the opcode-space allocation bits. For extended instructions, bits 5..2 are \texttt{L}, bits 1..0 begin the
opcode-space allocation bits, and byte 1 continues them. Thus \texttt{L} encodes the (:term:base.terms.encoded_instruction_length:) as
$3+L$ bytes directly in
Figure~\ref{fig:instruction-header-byte-formats}.
